# AI Dev Kit 全局开发规则

## 沟通与规划

- 实现前说明关键假设、任务边界与可验证的成功标准。
- 需求存在多种合理解释时，列出影响并确认目标。
- 优先采用路径更短、维护成本更低的方案。

## 实现原则

- KISS：使用解决当前问题所需的最少代码和概念。
- YAGNI：实现已明确要求的能力，避免预留推测性功能。
- DRY：提取真实重复的逻辑，保持单次使用代码直接清晰。
- SOLID：让模块职责单一、依赖方向清晰、接口保持专注。
- 采用外科手术式修改，保持现有风格与无关代码稳定。
- 在关键实现处添加简短注释，解释必要的意图或约束。

## 命令与代码检索

- Shell 命令优先通过 `rtk` 执行，以减少输出占用的上下文。
- 文件名、路径、标识符、字符串、正则与完整引用枚举使用 `rg`。
- 不知道名称时使用 `zvec_grep_search` 做语义定位，再用 `rg` 验证定义、调用方与影响范围。
- 修改公共接口或重构组件前，先列出定义、全部引用与修改计划。

## 验证与交付

- Bug 修复先形成可复现条件，再验证修复后的行为。
- 功能变更运行与风险相称的测试、构建、类型检查或 lint。
- 保持代码库干净，不提交临时文件、生成索引或废弃代码。
- 交付时说明已完成内容、验证结果与仍存在的明确风险。
